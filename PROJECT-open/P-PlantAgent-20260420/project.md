## 项目名称
**Plant-scOmics Fortress (PSOF)**
*中文名：植物单细胞多组学堡垒分析官*

## 项目介绍（196字）
PSOF 是专为植物科研设计的、具备“离线分析-主动解读”能力的双模态 Agent。该系统针对上游标准化流程后的个性化分析需求，通过本地化部署的 LLM 实现“Shell 交互式工作流”。Agent 根据用户对话生成分析代码并受控执行，在断网环境下确保核心数据安全。任务执行期间 Agent 进入“休眠”，待结果生成后自动“苏醒”，利用预构建的植物本地知识库对图表进行多维度解读。若遇报错，它将调用自检脚本定位问题，最终交付一份安全、闭环且深度解读的 HTML 交互式科研报告。

---

## 详细项目方案

### 核心创新点
1.  **离线“沙箱”分析逻辑：** 核心模型与知识库本地化，Agent 生成的代码在受限的 Shell 环境中运行，彻底杜绝数据外流风险。
2.  **异步“苏醒”机制：** 针对单细胞计算耗时的特点，设计了任务监听器。分析结束后，Agent 自动调取生成的 PDF/csv 进行“唤醒式”解读，无需人工守候。
3.  **报错检测脚本化：** 当 Python/R 脚本崩溃时，Agent 不仅仅输出错误信息，而是自动生成一个专门的 `debug_check.R` 脚本，探测内存占用、库版本及输入矩阵的完整性。

### 模型设计思路
* **分析端（The Executor）：** 采用微调后的代码模型（如 CodeLlama 或 Qwen-Coder），专注于生信常用库（Seurat, ArchR, monocle3）的代码生成。
* **解读端（The Interpreter）：** 预先将植物文献、Marker 数据库转化为本地向量库。
* **安全屏障：** 建立物理隔绝或逻辑隔绝层，所有的联网检索（RAG）仅在项目启动前的“背景收集阶段”进行，分析执行阶段完全离线。

### 模型架构



* **Commander (Shell Agent)：** 负责理解对话，生成 R/Python 脚本，控制子进程运行。
* **Sentinel (Monitor)：** 监控计算进程，负责在程序意外终止时收集 Traceback 堆栈信息。
* **Scribe (Post-Analyst)：** 读取分析产出的静态文件，结合本地知识库生成叙事性文本。

### 工作安排时间线（每日 2 小时）

| 周次 | 阶段 | 核心任务 |
| :--- | :--- | :--- |
| **W1** | **本地环境搭建** | 部署本地大模型（如通过 Ollama），配置受控的 Shell 运行环境。 |
| **W2** | **个性化分析 Prompt** | 优化针对单细胞下游分析（轨迹分析、细胞通讯）的代码生成提示词。 |
| **W3** | **报错诊断引擎** | 收集常见的生信报错（如内存溢出、基因名不匹配），构建诊断脚本库。 |
| **W4** | **离线知识库构建** | 将植物单细胞 Marker 数据库及相关综述转化为本地向量索引。 |
| **W5** | **自动苏醒与解读** | 开发文件监听逻辑，实现分析完成后的自动文本生成。 |
| **W6** | **安全性压测** | 模拟断网环境，使用水稻实测数据进行全流程闭环测试。 |

## 总结意义
1.  **绝对的数据安全：** 在封闭内网环境下提供超越 ChatGPT 的专业生信服务，满足高密级科研项目的需求。
2.  **降低分析门槛：** 学生只需通过对话描述分析意图（如：“帮我做一下 Cluster 3 和 5 之间的差异分析，并画出 Top 10 基因的火山图”），Agent 即可处理繁琐的代码实现。
3.  **闭环的纠错体验：** 解决了“报错即卡死”的现状。Agent 提供的自检脚本能让非专业学生快速发现是“内存不够”还是“分组列名写错”，极大地加速了项目交付进度。

**给你的技术实施建议：**
针对“报错检测”，你可以设计一个 **"Dry Run" (试运行)** 环节。Agent 在正式跑几百 GB 的数据前，先自动抽取 1000 个细胞做个“小样测试”，验证代码逻辑和库兼容性。这样在业余 2 小时的时间里，你能更高效地捕捉逻辑错误。
